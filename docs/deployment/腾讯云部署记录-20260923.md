## 部署过程中处理的问题

原 Next.js 16.2.12 与部分间接依赖存在已披露安全漏洞，已更新到 Next.js / eslint-config-next 16.3.6，并为相关间接依赖设置修复版本。`brace-expansion` 仅对受影响版本范围覆盖，避免破坏旧版 minimatch 的兼容性。业务计算与品质标准未调整。

原登录配置中密码哈希的 `$` 在 `.env.local` 中有 Next.js 所需的转义。直接复制自定义环境读取器结果到 systemd 会导致 JSON 无效；部署脚本改用 Next.js 自己的环境读取器，并在创建数据库角色前验证账号格式。云端配置已按相同规则重新生成，未更换原账号密码。后续构建必须加载云端环境文件，否则认证页面可能被错误预渲染。

IP 地址访问通常不发送 SNI，而腾讯云服务器网卡使用内网地址。公共证书签发后，需要在根 `/etc/caddy/Caddyfile` 的最前面设置以下全局选项，才能让普通浏览器及 curl 选择正确的公网 IP 证书。已通过带 SNI / 无 SNI 的对照检查验证并修正，未关闭证书校验。

```caddyfile
{
    default_sni 43.142.98.3
}
```

其余原网站配置保留，在末尾加入 `import /etc/caddy/paper-matching.caddy`。依据：[Caddy default_sni 官方说明](https://caddyserver.com/docs/caddyfile/options#default_sni)。

## 维护命令

以下命令在服务器执行，不打印环境文件内容：

```sh
sudo systemctl status paper-matching --no-pager
sudo journalctl -u paper-matching -n 50 --no-pager
sudo systemctl restart paper-matching
ss -lnt | grep -E ':(3000|15432) '
```

重新构建（先确认当前目录是要发布的版本；正式更新优先使用新版本目录）：

```sh
sudo systemd-run --unit=paper-matching-build --wait --pipe --collect \
  --property=User=paper-matching --property=Group=paper-matching \
  --property=WorkingDirectory=/opt/paper-matching/current \
  --property=EnvironmentFile=/etc/paper-matching/app.env \
  /usr/bin/node node_modules/next/dist/bin/next build
```

Windows 查看或恢复数据库连接：

```powershell
Get-ScheduledTask -TaskName 'PaperMatching-CloudDatabaseTunnel'
Start-ScheduledTask -TaskName 'PaperMatching-CloudDatabaseTunnel'
```
