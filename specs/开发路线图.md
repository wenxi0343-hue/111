# 项目开发路线图 (Development Roadmap)

## 0. 策略概览

**开发策略**：先搭地基，再做确定性计算，再打通配纸闭环，最后加入历史习惯、导出、AI 和增强能力。

**MVP 目标**：实现“维护基础数据 → 输入纸箱参数 → 生成三套配纸方案 → 查看成本/强度/设备状态 → 手动调整 → 保存历史”的最小业务闭环。

**排序原则**：

1. 公式、参数、原纸数据是地基，必须优先完成。
2. 面积、强度、成本、设备限制是产品可信度核心，必须早于推荐策略。
3. 推荐策略必须先按硬规则过滤，再考虑历史习惯评分。
4. AI 只负责解释文案，必须晚于确定性计算和推荐结果。
5. 导入导出和历史习惯分析重要，但不能阻塞最小配纸闭环。

**当前进度检测**：

- 当前已创建 `src/modules/` 目录及各业务模块占位。
- Phase 1.1 的“建立 Next.js 项目骨架”已完成。
- 已完成的是规划文档：`specs/技术栈.md`、`specs/项目结构.md`、`specs/开发规范.md`。
- 截至 2026-07-02，根据 `specs/features/` 任务规划和 `docs/开发记录/` 完成报告，数据库基础、简单登录保护、原纸资料建库、原纸代码映射、纸箱输入校验、确定性计算和推荐策略已完成或进入收尾状态。
- 后续开发顺序按“同一用户闭环合并”的原则执行：方案调整与历史保存合并，历史订单清洗与习惯提取合并，导出类能力合并，AI 正常理由与模板降级合并。

## 1. 依赖分析

### 1.1 地基模块

| 模块 | 依赖 | 被谁依赖 | 开发优先级 |
|------|------|----------|------------|
| `auth` | 无 | 所有页面和服务端动作 | 高 |
| `master-data` | `db` | `calculations`、`recommendation`、`import-export` | 高 |
| `paper-code` | `master-data` | `historical-orders`、`import-export` | 高 |
| `formulas` | `master-data` | `calculations`、`recommendation` | 高 |
| `box-spec` | 无 | `calculations`、`recommendation` | 高 |
| `db` | 基础设施 | 全部数据模块 | 高 |

### 1.2 核心业务模块

| 模块 | 依赖 | 产品价值 |
|------|------|----------|
| `calculations` | `box-spec`、`formulas`、`master-data` | 负责面积、强度、成本、设备限制，决定系统是否可信 |
| `recommendation` | `calculations`、`master-data` | 生成经济型、安全型、均衡型三套方案 |
| `scheme-adjustment` | `recommendation`、`calculations` | 支持用户手动调整并重新校核 |
| `history` / `matching-schemes` | `recommendation`、`db` | 保存最近 50 条历史方案 |

### 1.3 后置增强模块

| 模块 | 延后原因 |
|------|----------|
| `historical-orders` | 需要先有 `paper-code`、`master-data` 和基础推荐结果 |
| `import-export` | 导入要依赖主数据结构，导出要依赖方案结果结构 |
| `ai-reasoning` | AI 只能解释已有方案，不能参与核心计算 |
| `audit-log` | 追溯重要，但不阻塞 MVP 闭环 |
| 钉钉集成 | 属于入口和协同层，首版核心配纸闭环之后再做 |

## 2. 里程碑一：MVP (核心闭环)

> 目标：完成一套可信的单次配纸闭环。用户能维护基础数据，输入纸箱参数，生成三套方案，查看成本、强度和设备状态，并保存历史。

### Phase 1.1: 项目初始化与基础设施

- [x] **建立 Next.js 项目骨架**
  - **模块**：`src/app`、`src/shared`、配置文件
  - **说明**：创建 Next.js + TypeScript + Ant Design + pnpm 项目基础。
  - **完成标准**：项目能启动；ESLint、Prettier、TypeScript 检查可运行。
  - **开发提示词**：`使用 project-initialization，根据 specs/技术栈.md、specs/项目结构.md、specs/开发规范.md 初始化项目骨架。`

- [ ] **建立数据库与迁移基础**
  - **模块**：`src/db`
  - **说明**：配置 PostgreSQL、Drizzle、schema 拆分目录和迁移流程。
  - **完成标准**：能连接数据库；能执行一次空迁移或基础迁移。
  - **开发提示词**：`开发数据库基础设施，创建 src/db 结构、Drizzle 配置和基础迁移流程。`

- [ ] **实现简单登录保护**
  - **模块**：`auth`
  - **说明**：首版只做简单登录和服务端动作访问保护。
  - **完成标准**：未登录不能进入主应用；服务端动作能检查登录状态。
  - **开发提示词**：`开发 auth 模块，实现首版简单登录、会话保护和服务端动作鉴权。`

### Phase 1.2: 基础主数据

- [ ] **纸厂与原纸主数据**
  - **模块**：`master-data`
  - **说明**：维护纸厂、箱板纸、瓦纸，字段按 PRD 第 6 章。
  - **完成标准**：能新增、编辑、查询纸厂和原纸；原纸纸价单位为元/吨。
  - **开发提示词**：`开发 master-data 模块，实现纸厂、箱板纸、瓦纸的维护能力。`

- [ ] **基础参数维护**
  - **模块**：`master-data`、`formulas`
  - **说明**：维护设备限制、瓦楞系数、纸板厚度、层数费用系数、利用率分段。
  - **完成标准**：默认参数能初始化；参数可被计算模块读取。
  - **开发提示词**：`开发基础参数模块，内置 PRD 中的设备参数、瓦楞系数、纸板厚度和费用系数。`

- [ ] **原纸代码映射**
  - **模块**：`paper-code`
  - **说明**：支持原纸代码总表映射，必须区分大小写，支持 `aδ`。
  - **完成标准**：能识别匹配成功、无法匹配、疑似大小写错误、疑似克重误填。
  - **开发提示词**：`开发 paper-code 模块，实现原纸代码精确匹配、大小写候选提示和异常代码清单。`

### Phase 1.3: 确定性计算

- [ ] **纸箱输入与校验**
  - **模块**：`box-spec`
  - **说明**：实现纸箱尺寸、产品重量、堆码、生产数量等输入校验。
  - **完成标准**：满足 PRD 第 13 章输入校验；错误能定位到字段。
  - **开发提示词**：`开发 box-spec 模块，实现纸箱参数、产品信息、堆码和生产数量校验。`

- [ ] **面积计算**
  - **模块**：`calculations`
  - **说明**：实现三层、五层、七层普箱面积公式；七层支持两片成箱。
  - **完成标准**：覆盖搭舌、摇盖、高、总长、总宽、设备宽度判断；三/五层超宽标记不可生产。
  - **开发提示词**：`开发 calculations 面积计算，严格实现 PRD 8.2 和 8.3 的面积公式与设备限制。`

- [ ] **强度计算**
  - **模块**：`calculations`
  - **说明**：实现耐破、边压、空箱抗压，单位按 PRD。
  - **完成标准**：内部边压以 N/m 计算，展示 kN/m；空箱抗压单位 N。
  - **开发提示词**：`开发 calculations 强度计算，覆盖耐破、边压、空箱抗压和单位换算。`

- [ ] **成本计算**
  - **模块**：`calculations`
  - **说明**：实现原纸单价、用纸总价、加工费用、税金、含税成本。
  - **完成标准**：纸价按元/吨；瓦楞层使用瓦楞系数；生产数量影响原纸利用率。
  - **开发提示词**：`开发 calculations 成本计算，严格实现 PRD 8.8、8.9、8.10。`

### Phase 1.4: 方案推荐闭环

- [ ] **候选组合生成与硬规则过滤**
  - **模块**：`recommendation`
  - **说明**：从可用原纸中生成候选方案，并按数据完整、设备可生产、强度达标过滤。
  - **完成标准**：不达标方案不能进入达标推荐；数据不足时输出明确状态。
  - **开发提示词**：`开发 recommendation 候选生成与硬规则过滤，确保设备和强度不达标方案不会被推荐为达标。`

- [ ] **三套推荐方案**
  - **模块**：`recommendation`
  - **说明**：生成经济型、安全型、均衡型方案。
  - **完成标准**：经济型最低成本优先；安全型抗压富余率优先且排除超过 200%；均衡型按权重评分。
  - **开发提示词**：`开发 recommendation 三套方案排序：经济型、安全型、均衡型。`

- [ ] **配纸输入与结果页面**
  - **模块**：`src/app/(main)/matching`
  - **说明**：实现输入、生成、方案对比、状态展示。
  - **完成标准**：主流程不超过 3 步；结果展示成本、耐破、边压、空箱抗压、是否达标、是否可生产。
  - **开发提示词**：`开发 matching 页面，实现输入参数、生成方案和方案对比表。`

- [ ] **方案确认与保存闭环**
  - **模块**：`scheme-adjustment`、`history` / `matching-schemes`、`formulas`
  - **说明**：用户确认推荐方案，或调整瓦型、层数、纸厂、克重后重新计算，并保存最近 50 条历史方案。
  - **完成标准**：计算值和状态由系统重新生成，不允许用户手动改结果；保存输入、生产数量、价格快照、参数版本、推荐结果、是否手动调整和后续导出记录。
  - **开发提示词**：`开发方案确认与保存闭环：支持方案手动调整、重新计算、状态标记、价格/参数快照和最近 50 条历史方案保存。`

## 3. 里程碑二：功能完善 (Feature Complete)

> 目标：补齐导入导出、历史订单习惯分析、AI 解释和基础备份，让工具达到可正式试用状态。

### Phase 2.1: 历史订单建库与习惯提取

- [x] **原纸 Excel/CSV 导入**
  - **模块**：`import-export`、`master-data`
  - **说明**：导入纸厂、箱板纸、瓦纸。
  - **完成标准**：失败行可查看原因；导入内容作为不可信输入处理。
  - **开发提示词**：`已并入“原纸资料自动建库与可追溯维护”，后续不再作为独立开发批次。`

- [ ] **历史订单建库与习惯提取**
  - **模块**：`historical-orders`
  - **说明**：导入三年订单数据，基于 `paper-code` 清洗纸质代码，并统计公司常用层数、瓦型、纸厂、克重组合和产品类别偏好。
  - **完成标准**：识别空纸质、单代码、双代码、无法匹配、疑似大小写错误、疑似克重误填；输出按产品类别、尺寸区间、重量区间的配纸习惯摘要。
  - **开发提示词**：`开发历史订单建库与习惯提取：完成三年订单导入清洗、原纸代码异常清单和产品类别/尺寸/重量维度的常用配纸规律统计。`

### Phase 2.2: 历史习惯参与推荐

- [ ] **历史习惯评分与理由展示**
  - **模块**：`recommendation`
  - **说明**：把历史习惯变成推荐排序辅助分，并在方案中展示“符合哪些公司历史习惯”。
  - **完成标准**：历史习惯只能影响排序，不能覆盖强度、成本和设备硬规则；理由必须来自统计结果，不能凭空生成。
  - **开发提示词**：`开发历史习惯评分与理由展示：接入 recommendation 排序，并展示方案与历史订单习惯的相似点，但不得让不达标方案变为达标。`

### Phase 2.3: 导出与备份

- [ ] **方案 PDF 导出**
  - **模块**：`import-export`
  - **说明**：同时支持完整配纸报告 PDF 和适合快速分享的精简方案表 PDF。
  - **完成标准**：完整报告覆盖输入参数、方案对比、强度校核、成本和推荐结论；精简方案表包含成本、强度、是否达标、是否可生产；中文表格不截断。
  - **开发提示词**：`开发方案 PDF 导出：共用导出数据模型，支持完整配纸报告和精简方案表两种 PDF。`

- [ ] **导出备份能力**
  - **模块**：`import-export`
  - **说明**：支持原纸、公式/参数、历史方案的 Excel/JSON 备份，并补充基础备份恢复说明。
  - **完成标准**：原纸导出 Excel；参数导出 JSON；历史方案导出 Excel；运维人员能按文档完成基础备份和恢复。
  - **开发提示词**：`开发导出备份能力：支持原纸、公式参数、历史方案导出，并补充数据库、对象存储和导出备份说明。`

### Phase 2.4: AI 选型理由

- [ ] **AI 选型理由与模板降级**
  - **模块**：`ai-reasoning`
  - **说明**：服务端统一管理 AI 调用、超时、缓存、每日上限；AI 失败时使用模板说明。
  - **完成标准**：API Key 不暴露到客户端；AI 不参与核心计算；AI 失败不阻断方案生成；模板覆盖 PRD 第 12 章要求。
  - **开发提示词**：`开发 AI 选型理由与模板降级：封装服务端 AI Provider，并保证 AI 不可用时仍能生成基于计算结果的模板说明。`

## 6. 推荐开发顺序总览

```text
1. 项目骨架
2. 数据库基础
3. 简单登录
4. 主数据与基础参数
5. 原纸代码映射
6. 纸箱输入校验
7. 面积/强度/成本/设备限制
8. 推荐策略
9. 方案确认与保存闭环（方案调整 + 重新计算 + 历史方案保存 + 价格/参数快照）
10. 方案 PDF 导出（完整配纸报告 PDF + 精简方案表 PDF）
11. 历史订单建库与习惯提取（历史订单导入清洗 + 配纸习惯统计）
12. 历史习惯评分与理由展示（排序辅助分 + 公司习惯理由）
13. 导出备份能力（原纸/公式参数/历史方案导出 + 备份恢复说明）
14. AI 选型理由与模板降级（AI Provider + 模板理由）
15. 主流程测试补齐（生成 + 调整 + 保存 + 导出端到端）
16. 操作日志与参数追溯
17. 钉钉协同集成（钉钉入口登录 + 通知 + 文件归档）
18. 统计看板与成本趋势分析
19. 批量配纸、复杂权限、供应商价格自动同步等新需求澄清
```

> 当前后续开发建议从第 9 项“方案确认与保存闭环”开始。第 1-8 项及原纸资料导入相关能力已按现有任务规划完成或处于收尾状态，不再作为后续独立批次重复启动。

---

## 7. 使用指南

1. 每次只启动一个合并批次，避免多个用户闭环同时半成品。
2. 每个合并批次开发前，先用 `feature-requirements-clarification` 或已有 PRD 确认验收标准。
3. 进入编码时使用 `feature-implementation`，按测试优先方式完成。
4. 每完成一个合并批次，回到本文档勾选进度。
5. 涉及公式、原纸代码、历史订单、推荐策略的任务，必须补测试。
6. 历史习惯只能影响推荐排序，不能覆盖强度、成本和设备硬规则。
