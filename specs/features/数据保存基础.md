# 数据保存基础 — 功能需求说明书

## 1. 背景与价值

**为什么做**：项目已完成基础骨架，下一步需要先建立可靠的数据保存基础。后续纸厂、原纸、基础参数、历史方案、导出记录和 AI 理由缓存都依赖这一层。如果这一层不可用，业务功能即使页面完成，也无法稳定保存、追溯和恢复。

**做成什么样**：开发人员能配置数据连接、验证可用性、执行一次基础变更，并为后续业务模块提供清晰的数据保存边界。

**关联**：`specs/开发路线图.md` Milestone 1 / Phase 1.1 / 建立数据库与迁移基础。

---

## 2. 范围

### 本次做

- 提供数据连接基础，使项目能连接到 PostgreSQL。
- 提供数据变更记录能力，使后续数据结构调整可追溯、可重复执行。
- 提供初始数据入口，使后续已确认的默认参数可以按统一方式初始化。
- 提供连接失败、配置缺失、变更失败时的明确提示。
- 明确数据保存基础的项目边界，后续业务模块按既有目录结构接入。

### 本次不做

- 不重新确认或重新设计默认业务参数 — 默认参数已经在 PRD 和前序文档中确认。
- 不完整录入设备尺寸、瓦楞系数、纸板厚度、费用系数等默认参数 — 该能力在后续“基础参数维护”中落地。
- 不实现纸厂、箱板纸、瓦纸维护页面 — 属于后续 `master-data` 功能。
- 不实现历史方案保存 — 属于后续“历史方案保存”功能。
- 不实现导入、导出、报表或备份恢复 — 属于后续 `import-export` 和部署文档范围。
- 不实现复杂权限、多用户、多租户 — PRD V1.0 明确不包含。

## 4. 需求详述

### 4.1 核心流程

1. 开发人员配置数据连接信息。
2. 开发人员执行连接检查，确认项目能访问数据保存服务。
3. 开发人员执行一次基础变更，确认变更记录可生成、可执行、可追溯。
4. 后续业务模块基于统一边界接入数据保存基础。

### 4.2 交互规则

- 连接信息缺失时，应明确提示需要先配置连接信息。
- 连接失败时，应明确提示连接不可用，并避免展示敏感信息。
- 基础变更执行失败时，应明确提示失败原因，并保留可排查线索。
- 后续业务模块接入时，应能从项目结构中判断数据定义、变更记录、初始数据的放置位置。

### 4.3 业务规则

| 编号 | 规则 |
|------|------|
| BR-001 | 数据保存基础必须符合项目结构约定，由 `src/db` 承载连接、数据定义、变更记录和初始数据。 |
| BR-002 | 本功能只建立数据保存地基，不扩大到纸厂、原纸、基础参数、历史方案等业务功能实现。 |
| BR-003 | 默认业务参数已确认，本功能只提供初始化入口，不重新确认参数内容。 |
| BR-004 | 错误提示和日志不得暴露真实连接信息、密钥、原纸价格明细、公式参数敏感内容或底层堆栈。 |
| BR-005 | 数据基础必须服务于 PRD V1.0 的核心数据范围，包括纸厂、原纸、基础参数、历史方案、AI 缓存和导出记录。 |

## 5. 验收标准

### 5.1 正常流程 (Happy Path)

- [ ] **AC-001**: 数据连接可用
  - **Given** 开发人员已配置有效的数据连接信息
  - **When** 开发人员执行连接检查
  - **Then** 系统显示连接成功，并且不展示真实连接密码或完整连接信息

- [ ] **AC-002**: 基础变更可执行
  - **Given** 项目处于初始数据基础状态
  - **When** 开发人员执行第一次基础变更
  - **Then** 系统完成变更，并留下可追溯的变更记录

- [ ] **AC-003**: 数据保存边界清晰
  - **Given** 后续业务模块准备接入数据保存能力
  - **When** 开发人员查看项目结构
  - **Then** 能清楚识别数据定义、变更记录、初始数据分别应放置的位置

- [ ] **AC-004**: 支持后续默认参数初始化
  - **Given** 默认业务参数已经确认
  - **When** 后续功能需要初始化默认参数
  - **Then** 可以使用统一的初始数据入口接入，而不需要重新设计数据保存基础

### 5.2 边界与异常 (Edge & Error Cases)

- [ ] **AC-005**: 数据连接信息缺失
  - **Given** 数据连接信息未配置
  - **When** 开发人员执行连接检查或启动依赖数据保存的功能
  - **Then** 系统提示需要先配置数据连接信息，并阻止继续执行依赖数据保存的操作

- [ ] **AC-006**: 数据连接信息错误
  - **Given** 数据连接信息已配置但不可用
  - **When** 开发人员执行连接检查
  - **Then** 系统提示连接不可用，并且不展示真实密码、完整连接信息或底层错误堆栈

- [ ] **AC-007**: 基础变更执行失败
  - **Given** 基础变更执行过程中发生失败
  - **When** 开发人员查看执行结果
  - **Then** 系统显示失败状态和可排查原因，并避免让项目处于“看似成功但实际不完整”的状态

- [ ] **AC-008**: 重复执行基础变更
  - **Given** 某次基础变更已经成功执行
  - **When** 开发人员再次执行变更流程
  - **Then** 系统能够识别已完成状态，不重复产生冲突或破坏已有数据

### 5.3 业务规则验证 (Business Rules)

- [ ] **AC-009**: 遵守项目结构边界 ← BR-001
  - **Given** 开发人员新增数据保存相关内容
  - **When** 检查项目目录
  - **Then** 数据连接、数据定义、变更记录和初始数据均位于项目约定的数据保存目录内

- [ ] **AC-010**: 不扩大功能范围 ← BR-002
  - **Given** 本功能完成后
  - **When** 检查功能交付内容
  - **Then** 不包含纸厂维护、原纸维护、历史方案保存、导入导出、复杂权限或多租户能力

- [ ] **AC-011**: 默认参数不重新确认 ← BR-003
  - **Given** 默认业务参数已经在前序文档中确认
  - **When** 本功能设计和验收
  - **Then** 只要求具备初始化入口，不重新讨论默认参数取值

- [ ] **AC-012**: 敏感信息不外泄 ← BR-004
  - **Given** 数据连接、基础变更或后续接入过程出现错误
  - **When** 系统展示错误信息或记录排查信息
  - **Then** 不展示真实连接信息、密钥、原纸价格明细、公式参数敏感内容或底层堆栈

- [ ] **AC-013**: 服务后续核心数据范围 ← BR-005
  - **Given** 后续纸厂、原纸、基础参数、历史方案、AI 缓存和导出记录功能陆续开发
  - **When** 这些功能需要接入数据保存能力
  - **Then** 当前数据保存基础能够作为统一地基继续扩展，无需新增项目顶层模块
