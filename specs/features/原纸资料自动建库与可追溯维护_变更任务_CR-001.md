# 原纸资料自动建库与可追溯维护 — 变更任务 CR-001

## 1. 变更概览

**CR 编号**：CR-001
**变更标题**：主数据多来源导入页面闭环收口
**变更类型**：扩展
**提出日期**：2026-06-30
**关联功能**：原纸资料自动建库与可追溯维护

**变更原因**：主数据底层已具备纸价表和物理指标/标准表解析、自动关联、确认入库能力，但页面上传入口和 `previewMasterDataImport` 仍主要围绕原纸代码表，用户无法在页面完整完成纸价表/指标表的预览、待确认处理和确认入库闭环。

**变更目标**：让系统维护人员可以在主数据页面选择原纸代码表、纸价表、物理指标/标准表三种导入来源，并使用同一套预览、待确认、确认入库流程完成主数据补齐。

---

## 2. 影响范围

### 需求影响

- 新增 AC-026：多来源导入页面闭环。
- 不改变原纸代码唯一、原纸编码辅助、待确认不静默猜测、历史订单不进入本功能等既有规则。

### 技术影响

- 不新增数据库表。
- 不新增依赖。
- 扩展 `previewMasterDataImport`，按 `sourceType` 分发到原纸代码表、纸价表、物理指标/标准表解析和预览逻辑。
- 复用现有 `confirmMasterDataImport`、`resolveMasterDataImportRow`、导入批次和导入行结构。

### 页面影响

- `ImportUploadPanel` 来源选择开放三种来源。
- `ImportPreviewTable` 需要支持不同来源的行展示。
- 待确认行需要在导入预览区展示并允许用户选择候选原纸。
- 确认入库成功后刷新原纸资料库列表。

## 3. 增量开发任务

### Task-15: 多来源预览动作分发

**通俗解释**：用户选了哪种表，服务端就按哪种表去解析和生成预览，而不是永远当成原纸代码表。

**做什么**：扩展 `previewMasterDataImport`；支持 `paper_code_table`、`paper_price_table`、`quality_standard_table` 三种来源；按来源调用 `parsePaperCodeWorkbook` / `parsePaperCodeCsv`、`parsePaperPriceWorkbook`、`parseQualityStandardWorkbook`；按来源调用 `createPaperCodeImportPreview`、`createPaperPriceImportPreview`、`createQualityStandardImportPreview`；保存统一导入预览批次和行数据。

**涉及文件**：
- `src/server/actions/master-data-actions.ts`
- `src/modules/master-data/import-commit.ts`
- `src/modules/master-data/import-preview.ts`
- `tests/integration/master-data/multi-source-import-actions.test.ts`

**参考**：技术方案 4 / `previewMasterDataImport` CR-001 补充、技术方案 5 / 多来源导入页面闭环 → AC-004, AC-005, AC-007, AC-026

**依赖**：Task-05, Task-06, Task-07, Task-08, Task-09, Task-14

**预估工时**：70 分钟

**验证标准**：
- [ ] 选择 `paper_price_table` 并上传有效纸价表 → 返回 `ok: true`，摘要包含更新或待确认数量，并保存批次 `sourceType: "paper_price_table"`。
- [ ] 选择 `quality_standard_table` 并上传有效指标表 → 返回 `ok: true`，摘要包含更新或标准规则数量，并保存批次 `sourceType: "quality_standard_table"`。
- [ ] 纸价表出现多候选原纸 → 预览行状态为 `pending`，并返回候选原纸 ID。
- [ ] 指标表只能表达纸类标准 → 预览行展示标准规则提示，不要求目标原纸。
- [ ] 上传 `.xls` 或不支持来源 → 返回 `VALIDATION_ERROR`，不解析、不保存预览。

### Task-16: 多来源导入页面闭环

**通俗解释**：页面上可以选三种导入来源，纸价和指标表也能看到预览；如果有待确认，用户能在页面选对原纸，再确认入库。

**做什么**：扩展 `ImportUploadPanel` 来源选择；按来源展示文件提示和预览摘要；让 `ImportPreviewTable` 支持纸价更新、指标更新、标准规则、待确认和失败行；在预览区域接入 `PendingMatchTable`；调用 `resolveMasterDataImportRow` 处理待确认行；确认入库成功后刷新资料库列表。

**涉及文件**：
- `src/app/(main)/master-data/_components/import-upload-panel.tsx`
- `src/app/(main)/master-data/_components/import-preview-table.tsx`
- `src/app/(main)/master-data/_components/pending-match-table.tsx`
- `src/app/(main)/master-data/_components/paper-material-list-panel.tsx`
- `tests/integration/master-data/master-data-multi-source-page.test.tsx`

**参考**：需求 AC-026、技术方案 2 / 模块职责、技术方案 5 / 多来源导入页面闭环

**依赖**：Task-15

**预估工时**：90 分钟

**验证标准**：
- [ ] 页面来源下拉包含“原纸代码表”“纸价表”“物理指标/标准表”。
- [ ] 用户选择纸价表并上传成功 → 页面展示更新、待确认、失败摘要和纸价变化字段。
- [ ] 用户选择物理指标/标准表并上传成功 → 页面展示指标补充或标准规则结果。
- [ ] 页面收到待确认行 → 展示候选原纸，用户选择候选后可提交确认关联。
- [ ] 待确认处理完成后点击确认入库 → 页面展示入库成功摘要，并刷新原纸资料库列表。
- [ ] 动作返回业务错误 → 页面展示业务提示，不展示堆栈或内部异常。
