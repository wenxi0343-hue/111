# 简单登录保护 — 功能需求说明书

## 1. 背景与价值

**为什么做**：项目已完成数据库基础设施，下一步需要为云端 Web 应用建立最小登录保护。原纸价格、公式参数、历史方案和导出报告都属于公司核心资产，不能在没有登录保护的情况下开放访问。

**做成什么样**：用户使用已配置的固定账号登录后进入主应用；同一浏览器 7 天内保持登录；未登录或登录过期时不能进入主应用，也不能执行关键业务操作。

**关联**：`specs/开发路线图.md` Milestone 1 / Phase 1.1 / 实现简单登录保护。

---

## 2. 范围

### 本次做

- 提供登录入口，使用户可以用已配置账号和密码登录。
- 支持少量固定账号登录，但所有账号进入同一主应用，不区分角色权限。
- 登录成功后，同一浏览器保持 7 天登录状态。
- 未登录访问主应用时，要求先登录。
- 登录过期后，要求重新登录。
- 支持用户主动退出登录。
- 对生成方案、保存、导入、导出等关键业务操作做登录检查。
- 登录失败、登录配置不可用、未登录访问等场景使用安全提示，不暴露敏感信息。

### 本次不做

- 不做注册、找回密码、验证码 — 首版只面向内部固定账号。
- 不做工艺、销售、管理员等角色权限区分 — PRD V1.0 明确不做复杂权限。
- 不做钉钉登录 — 钉钉入口和登录属于后续增强能力。
- 不做多公司、多租户 — PRD V1.0 明确不包含。
- 不做操作日志 — `audit-log` 属于后续追溯与稳定性阶段。
- 不做账号自助管理页面 — 首版只要求支持已配置的少量固定账号。

## 4. 需求详述

### 4.1 核心流程

1. 用户打开系统主应用。
2. 如果用户未登录，系统要求用户先进入登录页。
3. 用户输入已配置账号和密码。
4. 登录成功后，用户进入主应用。
5. 同一浏览器 7 天内再次访问时，用户可继续进入主应用。
6. 用户主动退出或登录状态过期后，再次访问主应用需要重新登录。
7. 用户执行关键业务操作时，系统先确认用户已登录。

### 4.2 交互规则

- 登录页只提示必要信息，不展示内部配置细节。
- 登录失败时统一提示“账号或密码错误”，不说明是账号不存在还是密码错误。
- 登录服务配置不可用时，提示“登录服务暂不可用，请联系系统维护人员”。
- 用户提交登录时，应避免重复提交造成多次登录请求。
- 用户已登录时访问登录页，应能回到主应用。
- 用户退出登录后，应返回登录页。
- 登录过期时，应要求重新登录，并提示登录状态已过期。

### 4.3 业务规则

| 编号 | 规则 |
|------|------|
| BR-001 | 首版只支持已配置的少量固定账号，不提供注册、找回密码或账号自助管理。 |
| BR-002 | 首版所有有效账号拥有同一访问范围，不区分工艺、销售、管理员等角色权限。 |
| BR-003 | 登录有效期为 7 天，从登录成功时开始计算；过期后必须重新登录。 |
| BR-004 | 未登录或登录过期时，用户不能进入主应用。 |
| BR-005 | 生成方案、保存、导入、导出等关键业务操作必须要求用户已登录。 |
| BR-006 | 登录失败提示不得暴露账号是否存在、密码细节、内部错误或底层异常信息。 |
| BR-007 | 登录相关提示不得暴露真实密钥、原纸价格明细、公式参数敏感内容或底层堆栈。 |
| BR-008 | 本功能不得扩大到复杂权限、钉钉登录、多公司、多租户或操作日志。 |

## 5. 验收标准

### 5.1 正常流程 (Happy Path)

- [ ] **AC-001**: 未登录访问主应用
  - **Given** 用户当前未登录
  - **When** 用户打开主应用页面
  - **Then** 系统要求用户先登录，并展示登录入口

- [ ] **AC-002**: 登录页可用
  - **Given** 用户位于登录页
  - **When** 用户查看登录页
  - **Then** 用户可以看到账号、密码输入项和登录按钮

- [ ] **AC-003**: 有效账号登录成功
  - **Given** 用户位于登录页，且输入已配置的有效账号和密码
  - **When** 用户提交登录
  - **Then** 系统提示或表现为登录成功，并进入主应用

- [ ] **AC-004**: 7 天内保持登录
  - **Given** 用户已成功登录，且距离登录成功未超过 7 天
  - **When** 用户在同一浏览器再次打开主应用
  - **Then** 用户可以直接进入主应用，不需要重新登录

- [ ] **AC-005**: 用户主动退出登录
  - **Given** 用户已登录
  - **When** 用户点击退出登录
  - **Then** 系统清除登录状态并返回登录页

### 5.2 边界与异常 (Edge & Error Cases)

- [ ] **AC-006**: 错误账号或密码
  - **Given** 用户位于登录页，且输入错误账号或错误密码
  - **When** 用户提交登录
  - **Then** 系统拒绝登录，并提示“账号或密码错误”

- [ ] **AC-007**: 多次登录失败仍使用统一提示
  - **Given** 用户连续多次输入错误账号或密码
  - **When** 用户再次提交登录
  - **Then** 系统仍只提示“账号或密码错误”，不提示账号是否存在

- [ ] **AC-008**: 登录状态过期
  - **Given** 用户曾经登录成功，但登录成功时间已经超过 7 天
  - **When** 用户打开主应用
  - **Then** 系统要求用户重新登录，并提示登录状态已过期

- [ ] **AC-009**: 未登录执行关键业务操作
  - **Given** 用户未登录或登录状态已过期
  - **When** 用户尝试执行生成方案、保存、导入或导出等关键业务操作
  - **Then** 系统拒绝执行，并提示需要先登录

- [ ] **AC-010**: 登录配置不可用
  - **Given** 登录账号配置缺失或登录服务不可用
  - **When** 用户尝试登录
  - **Then** 系统拒绝登录，并提示“登录服务暂不可用，请联系系统维护人员”

- [ ] **AC-011**: 已登录访问登录页
  - **Given** 用户已登录
  - **When** 用户打开登录页
  - **Then** 系统引导用户回到主应用

### 5.3 业务规则验证 (Business Rules)

- [ ] **AC-012**: 固定账号范围 ← BR-001
  - **Given** 简单登录保护功能完成
  - **When** 检查用户可见功能
  - **Then** 系统不提供注册、找回密码、验证码或账号自助管理入口

- [ ] **AC-013**: 不区分角色权限 ← BR-002
  - **Given** 系统存在多个有效固定账号
  - **When** 任一有效账号登录成功
  - **Then** 用户进入同一主应用，不出现工艺、销售、管理员等权限差异

- [ ] **AC-014**: 关键操作必须登录 ← BR-004, BR-005
  - **Given** 后续功能接入生成方案、保存、导入或导出等关键业务操作
  - **When** 这些操作被触发
  - **Then** 操作执行前必须能确认用户处于已登录状态

- [ ] **AC-015**: 敏感信息不外泄 ← BR-006, BR-007
  - **Given** 登录失败、登录过期、登录配置不可用或拒绝访问场景发生
  - **When** 系统展示提示
  - **Then** 提示中不暴露账号是否存在、密码、密钥、内部错误、底层堆栈、原纸价格明细或公式参数敏感内容

- [ ] **AC-016**: 不扩大功能范围 ← BR-008
  - **Given** 本功能完成后
  - **When** 检查功能交付内容
  - **Then** 不包含复杂角色权限、钉钉登录、多公司、多租户或操作日志能力
