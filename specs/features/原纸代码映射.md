# 原纸代码映射 — 功能需求说明书

## 1. 背景与价值

**为什么做**：原纸代码是历史订单、纸价、原纸资料之间最关键的业务标识。当前主数据导入已经能按原纸代码做精确关联，但后续三年历史订单清洗会遇到更多脏数据：大小写写错、把克重写进纸质栏、空纸质、单代码、双代码、以及 `aδ` 这类特殊历史代码。系统需要先具备稳定的原纸代码映射和异常识别能力，后续历史订单导入才不会把错误代码静默匹配成错误原纸。

**做成什么样**：用户或后续导入流程提交一个或多个原纸代码后，系统能够精确识别可匹配原纸；对不能精确匹配的代码，给出清晰状态和人工确认所需的候选信息；对疑似克重、空值、大小写错误和多候选情况形成异常清单。

**关联**：`specs/开发路线图.md` Milestone 1 / Phase 1.2 / 原纸代码映射；同时为 Milestone 2 / Phase 2.1 / 历史订单数据导入与清洗提供前置能力。

---

## 2. 范围

### 本次做

- 按原纸代码进行精确匹配，必须区分大小写。
- 支持 `aδ` 等非普通英文字母历史代码。
- 对大小写不一致但字符相同的代码输出疑似候选，不自动替换。
- 对 `dc` 这类可能同时对应 `dC`、`DC` 的代码提示人工确认。
- 识别疑似把克重误填为原纸代码的输入，例如 `250g`、`250G`、`250`。
- 识别空代码、纯空格代码和无法匹配代码。
- 支持单个代码和一组代码的映射结果输出。
- 输出异常清单，便于后续历史订单导入展示失败行和待确认原因。

### 本次不做

- 不导入近三年订单数据。
- 不解析历史订单 Excel 字段。
- 不提取历史配纸习惯。
- 不修改主数据导入页面。
- 不自动创建或修改原纸资料。
- 不把疑似候选自动当作匹配成功。

## 4. 需求详述

### 4.1 核心流程

1. 系统维护人员已经在主数据中维护或导入原纸资料，原纸资料中包含原纸代码。
2. 用户或后续导入流程提交一个原纸代码，或提交一组原纸代码。
3. 系统优先按原纸代码原样精确匹配。
4. 精确匹配成功时，系统返回匹配成功结果。
5. 精确匹配失败时，系统检查是否存在大小写不同但字符相同的候选。
6. 如果只有一个大小写候选，系统提示疑似大小写错误。
7. 如果存在多个大小写候选，系统提示无法唯一确定，需要人工确认。
8. 如果输入看起来像克重，系统提示疑似把克重填入原纸代码。
9. 如果没有任何候选，系统提示无法匹配。
10. 批量处理时，系统汇总匹配成功、待确认、失败和异常原因。

### 4.2 交互规则

- 精确匹配成功和疑似候选必须清楚区分。
- 大小写不一致时不得自动修正。
- 多候选时必须提示人工确认。
- 异常原因必须使用业务语言，便于用户理解和修正。
- 批量结果必须保留每个输入代码的原始写法。
- 空代码和疑似克重必须进入异常清单。

### 4.3 业务规则

| 编号 | 规则 |
|------|------|
| BR-001 | 原纸代码匹配必须区分大小写。 |
| BR-002 | `aδ` 等特殊历史代码属于合法原纸代码，不得因包含非普通英文字母而被拒绝。 |
| BR-003 | 疑似候选只能用于提示，不得自动替换为匹配成功。 |
| BR-004 | 同一个输入代码匹配到多个大小写候选时，必须进入待确认。 |
| BR-005 | 看起来像克重的输入必须提示“疑似克重误填”，不能当作普通无法匹配吞掉。 |
| BR-006 | 批量映射必须逐条保留原始输入、匹配状态和原因。 |

## 5. 验收标准

### 5.1 正常流程 (Happy Path)

- [ ] **AC-001**: 精确匹配原纸代码
  - **Given** 资料库中存在原纸代码 `r2`
  - **When** 用户提交原纸代码 `r2`
  - **Then** 系统返回匹配成功，并指向该原纸

- [ ] **AC-002**: 区分大小写匹配
  - **Given** 资料库中同时存在原纸代码 `dC` 和 `DC`
  - **When** 用户提交原纸代码 `dC`
  - **Then** 系统只返回 `dC` 对应原纸为匹配成功，不把 `DC` 当作同一个代码

- [ ] **AC-003**: 支持特殊历史代码
  - **Given** 资料库中存在原纸代码 `aδ`
  - **When** 用户提交原纸代码 `aδ`
  - **Then** 系统返回匹配成功，并保留 `aδ` 的原始写法

- [ ] **AC-008**: 批量映射返回逐条结果
  - **Given** 用户提交一组原纸代码，其中包含可匹配、待确认和无法匹配的代码
  - **When** 系统执行批量映射
  - **Then** 系统逐条展示原始代码、匹配状态、匹配结果或异常原因

### 5.2 边界与异常 (Edge & Error Cases)

- [ ] **AC-004**: 单一大小写候选提示
  - **Given** 资料库中存在原纸代码 `DC`，但不存在 `dc`
  - **When** 用户提交原纸代码 `dc`
  - **Then** 系统不返回匹配成功，而是提示疑似大小写错误，并展示候选 `DC`

- [ ] **AC-005**: 多个大小写候选进入待确认
  - **Given** 资料库中同时存在原纸代码 `dC` 和 `DC`，但不存在 `dc`
  - **When** 用户提交原纸代码 `dc`
  - **Then** 系统提示无法唯一确定，并展示候选 `dC` 和 `DC` 供人工确认

- [ ] **AC-006**: 疑似克重误填
  - **Given** 资料库中不存在原纸代码 `250g`
  - **When** 用户提交原纸代码 `250g`
  - **Then** 系统提示该输入疑似克重误填，不把它作为普通原纸代码匹配成功

- [ ] **AC-007**: 空代码进入异常清单
  - **Given** 用户提交空字符串或只包含空格的原纸代码
  - **When** 系统执行映射
  - **Then** 系统提示原纸代码为空，并将该记录放入异常清单

- [ ] **AC-009**: 无候选代码无法匹配
  - **Given** 资料库中不存在原纸代码 `unknown`，也不存在大小写候选
  - **When** 用户提交原纸代码 `unknown`
  - **Then** 系统返回无法匹配，并保留原始输入供用户修正

### 5.3 业务规则验证 (Business Rules)

- [ ] **AC-010**: 疑似候选不得自动替换
  - **Given** 用户提交的代码没有精确匹配，但存在一个或多个疑似候选
  - **When** 系统返回映射结果
  - **Then** 系统必须标记为待确认或异常，而不是直接替换为候选代码

- [ ] **AC-011**: 批量异常清单可用于后续导入
  - **Given** 批量映射中存在空代码、疑似克重、大小写候选和无法匹配代码
  - **When** 用户查看批量映射结果
  - **Then** 系统按原因汇总异常清单，并能区分“需要人工确认”和“无法匹配”

- [ ] **AC-012**: 本功能不处理历史订单数据
  - **Given** 原纸代码映射功能完成后
  - **When** 检查功能交付范围
  - **Then** 系统不包含历史订单文件导入、订单字段解析或历史习惯统计能力
