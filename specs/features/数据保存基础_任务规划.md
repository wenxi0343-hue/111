## 2. 开发任务

> 本功能是纯基础设施能力，没有用户页面。阶段按“开发人员可独立验证的行为”组织，并尽量合并低风险小任务以缩短开发时间。

### 阶段一：开发人员能建立可追溯的数据地基

**阶段完成标准**：开发人员能看到 `system_metadata` 基线表定义和基础迁移文件，且确认没有提前创建业务表。

---

#### [x] Task-01: 基线 schema 与基础迁移 🔒⚠️

**通俗解释**：系统先立好数据库地基，并留下第一条可追溯的数据变更记录。

**做什么**：新增 `system_metadata` schema，替换 schema 占位导出；调整 Drizzle 配置缺失连接时的提示；生成基础迁移文件。只创建非业务基线表，不创建纸厂、原纸、参数、历史方案等业务表。

**涉及文件**：`src/db/schema/system.ts`、`src/db/schema/index.ts`、`drizzle.config.ts`、`src/db/migrations/*`、`tests/integration/db/schema-and-migration.test.ts`

**参考**：技术方案 3、4、5、6、7 → AC-002, AC-003, AC-005, AC-007, AC-008, AC-009, AC-010, AC-012, AC-013

**依赖**：无

**预估工时**：75 分钟

**验证标准**（TDD RED 阶段直接转化为测试用例）：
- [ ] 导入 `src/db/schema` 时，能获取名为 `system_metadata` 的 schema 导出。
- [ ] `system_metadata` 包含 `id`、`key`、`value`、`description`、`created_at`、`updated_at` 字段，且 `key` 具备唯一约束或唯一索引定义。
- [ ] 当 `DATABASE_URL` 缺失时加载 Drizzle 配置 → 不使用空字符串静默继续，返回或抛出脱敏的配置提示。
- [ ] 生成的迁移文件位于 `src/db/migrations`，包含 `CREATE TABLE "system_metadata"`。
- [ ] schema 导出和迁移文件不包含 `paperFactories`、`paper_factories`、`paperMaterials`、`paper_materials`、`formulaParameters`、`formula_parameters`、`matchingSchemes`、`matching_schemes`、`historicalOrders`、`historical_orders`、`aiCache`、`ai_cache`。

---

### 阶段二：开发人员能检查数据库连接

**阶段完成标准**：开发人员可以执行 `db:check`；连接成功时看到成功提示，配置缺失或连接失败时看到脱敏后的明确提示。

---

#### [x] Task-02: 数据连接与检查命令 🔒

**通俗解释**：开发人员可以用一条命令快速知道数据库能不能连上。

**做什么**：替换 `src/db/index.ts` 占位内容，提供读取 `DATABASE_URL`、创建连接池、Drizzle 实例、连接检查、关闭连接和脱敏错误结果；新增 `scripts/check-database.ts`，并在 `package.json` 增加 `db:check`。

**涉及文件**：`src/db/index.ts`、`scripts/check-database.ts`、`package.json`、`tests/integration/db/database-check.test.ts`

**参考**：技术方案 4、5、6、8 → AC-001, AC-005, AC-006, AC-012

**依赖**：Task-01

**预估工时**：65 分钟

**验证标准**（TDD RED 阶段直接转化为测试用例）：
- [ ] 当 `DATABASE_URL` 为空字符串或未定义时，调用连接配置读取函数 → 返回失败结果，错误码为 `DATABASE_URL_MISSING`，提示包含“需要先配置数据连接信息”。
- [ ] 当 `DATABASE_URL` 为 `postgresql://user:secret-password@localhost:5432/app` 且连接失败时，连接检查结果 → 返回失败，提示包含“数据库连接不可用”，且不包含 `secret-password`、完整连接串、`postgresql://` 或底层堆栈。
- [ ] 当注入的查询执行器返回成功时，连接检查结果 → 返回成功，提示为“数据库连接成功”。
- [ ] `package.json` scripts 中存在 `db:check`，且命令指向 `scripts/check-database.ts`。
- [ ] 模拟脚本成功和失败时 → 成功退出码为 0，失败退出码为 1，输出均不泄露密码或完整连接串。

### 阶段三：开发人员能运行初始化入口

**阶段完成标准**：开发人员可以执行 `db:seed`；当前只写入非业务基线元信息，重复执行不会冲突，后续默认参数可从同一入口接入。

---

#### [x] Task-03: 初始化入口与命令

**通俗解释**：系统有了统一的初始化入口，以后默认参数从这里进，不会散落在各处。

**做什么**：新增 `src/db/seeds/index.ts`，写入 `schema_baseline` 元信息并保证幂等；新增 `scripts/seed-database.ts`，并在 `package.json` 增加 `db:seed`。

**涉及文件**：`src/db/seeds/index.ts`、`scripts/seed-database.ts`、`package.json`、`tests/integration/db/database-seed.test.ts`

**参考**：技术方案 4、5、6、8 → AC-004, AC-007, AC-008, AC-010, AC-011, AC-012, AC-013

**依赖**：Task-01, Task-02

**预估工时**：50 分钟

**验证标准**（TDD RED 阶段直接转化为测试用例）：
- [ ] 当 `system_metadata` 中不存在 `schema_baseline` 时，执行 seed 函数 → 写入 `key = "schema_baseline"` 的记录。
- [ ] 当 `schema_baseline` 已存在时，执行 seed 函数 → 不插入重复记录，可跳过或更新 `updated_at`。
- [ ] 当基础表不存在或查询失败时，执行 seed 函数 → 返回失败结果，提示先执行数据库迁移。
- [ ] seed 函数不会写入设备尺寸、瓦楞系数、纸板厚度、费用系数、纸厂、原纸或历史方案数据。
- [ ] `package.json` scripts 中存在 `db:seed`，且命令指向 `scripts/seed-database.ts`。
- [ ] 模拟 seed 成功和失败时 → 成功退出码为 0，失败退出码为 1，失败输出不包含密码、完整连接串或底层堆栈。
