# 项目结构

## 1. 设计依据

本目录结构基于以下已确认文档：

- `纸箱自动配纸工具-PRD-V1.0.md`
- `specs/技术栈.md`

当前项目暂未提供 `specs/产品概述.md`、`specs/PROJECT-CONTEXT.md`、`specs/GUARDRAILS.md`，因此本结构以 PRD 作为业务边界来源，以技术栈文档作为技术边界来源。

核心技术栈：

- Next.js + React + TypeScript
- Ant Design
- PostgreSQL + Drizzle ORM
- 对象存储
- ExcelJS + PapaParse
- Playwright/Chromium PDF
- 服务端 AI Provider

核心业务板块：

- 单次配纸输入
- 原纸、纸厂、基础参数维护
- 面积、强度、成本计算
- 设备限制校验
- 经济型、安全型、均衡型推荐
- 方案调整与重新校核
- 历史方案保存与导出
- 原纸代码映射
- 三年历史订单习惯分析
- AI 选型理由

## 3. 关键目录说明 (Key Directories)

### 3.1 `src/app/`

`src/app/` 只放页面、路由和页面级布局，遵循 Next.js App Router 结构。

页面层职责：

- 展示表单、表格、弹窗、状态标记。
- 触发生成方案、导入、导出、保存等操作。
- 读取服务端返回的结果并展示。

页面层禁止直接承载：

- 面积、强度、成本公式。
- 原纸组合搜索策略。
- 原纸代码映射规则。
- AI 选型理由拼装。
- 数据库读写细节。

### 3.2 `src/modules/`

`src/modules/` 是业务核心。每个模块围绕一个清晰业务能力组织，避免把所有逻辑堆进 `utils` 或页面组件中。

| 模块 | 职责 |
|------|------|
| `auth` | 首版简单登录、会话状态、访问保护 |
| `master-data` | 纸厂、箱板纸、瓦纸、基础参数维护 |
| `paper-code` | 原纸代码到原纸资料的映射，处理大小写敏感和异常代码 |
| `box-spec` | 纸箱输入字段、尺寸规则、结构类型、成箱方式 |
| `formulas` | 公司默认公式、参数版本、公式口径管理 |
| `calculations` | 面积、耐破、边压、空箱抗压、成本、设备限制 |
| `recommendation` | 经济型、安全型、均衡型方案筛选与排序 |
| `scheme-adjustment` | 用户修改方案后重新校核和状态标记 |
| `historical-orders` | 三年历史订单数据清洗、配纸习惯提取、相似订单评分 |
| `import-export` | Excel/CSV 导入，PDF/Excel/JSON 导出 |
| `ai-reasoning` | AI 选型理由生成、缓存、限额、模板降级 |
| `audit-log` | 保存重要操作记录，便于追溯问题 |

### 3.3 `src/db/`

`src/db/` 只处理数据库相关内容。

建议按模块拆分 schema，例如：

- `paper-factories`
- `paper-materials`
- `formula-parameters`
- `matching-schemes`
- `historical-orders`
- `ai-cache`

数据库层不得包含页面逻辑，也不得直接拼装用户可见文案。

### 3.4 `src/server/`

`src/server/` 负责连接页面和业务模块。

典型职责：

- 接收页面请求。
- 做登录检查和输入保护。
- 调用 `src/modules/` 中的业务能力。
- 调用数据库和对象存储。
- 返回页面需要的结果。

`server/actions` 用于主流程，例如：

- 生成配纸方案。
- 保存历史方案。
- 导入原纸数据。
- 导入历史订单数据。
- 导出报告。

`server/jobs` 用于耗时或批量任务，例如：

- 三年订单数据清洗。
- 历史习惯统计。
- 批量生成导入失败报告。
- 生成 PDF。

### 3.5 `src/shared/`

`src/shared/` 只放非业务通用能力。

可以放：

- 通用按钮、表格、状态标签。
- 日期、数字、金额格式化。
- 通用字段校验。
- 通用类型。

不可以放：

- 面积公式。
- 强度公式。
- 成本公式。
- 推荐策略。
- 原纸代码业务规则。

这些必须留在对应业务模块中。

## 4. 核心模块边界

### 4.1 `paper-code`

该模块专门处理原纸代码映射。

必须支持：

- 使用“原纸代码总表”作为映射来源。
- 原纸代码精确匹配，必须区分大小写。
- 允许 `aδ` 这类非普通英文字母代码。
- 对匹配失败的代码给出疑似候选，但不自动替换。
- 对 `dc` 这类同时可能对应 `dC`、`DC` 的代码提示人工确认。
- 输出无法匹配、疑似大小写错误、疑似填入克重等异常清单。

该模块是历史订单习惯分析的前置模块。

### 4.2 `historical-orders`

该模块负责把三年订单数据转为可用于推荐的“公司配纸习惯”。

必须遵守：

- 历史习惯只能影响推荐排序，不能覆盖公式、强度和设备限制。
- 历史订单必须先通过原纸代码映射清洗。
- 历史订单中的价格、公式、设备口径可能与当前不同，不能直接当作当前成本结论。
- 单代码、双代码、空代码等异常记录必须单独标记。

建议输出：

- 按产品类别的常用层数。
- 按尺寸区间的常用瓦型。
- 按重量区间的常用配纸组合。
- 按客户或产品名称的历史偏好。
- 常用纸厂、克重和组合频率。
- 历史习惯评分，供推荐模块排序使用。

### 4.3 `calculations`

该模块负责所有确定性计算。

包含：

- 三层、五层、七层面积。
- 七层两片成箱面积。
- 设备尺寸限制。
- 耐破。
- 边压。
- 空箱抗压。
- 原纸利用率。
- 成本、税金、含税成本。

该模块输出的是客观计算结果，不负责解释文案，也不负责 AI 理由。

### 4.4 `recommendation`

该模块负责从候选配纸组合中选出方案。

推荐顺序建议：

1. 先按硬规则过滤：数据完整、设备可生产、强度达标。
2. 再按方案类型排序：经济型、安全型、均衡型。
3. 最后引入历史习惯评分，优先推荐更符合公司过往习惯的方案。

历史习惯评分不得让不达标方案变成达标方案。

### 4.5 `ai-reasoning`

该模块只负责生成“为什么推荐这个方案”的说明。

必须遵守：

- AI 不参与核心计算。
- AI 不得编造没有计算依据的结论。
- AI 失败、超时、达到每日上限时，使用模板理由。
- AI 输出必须基于服务端已计算出的结果。

## 5. 文件放置规则 (Placement Rules)

| 文件类型 | 放置位置 | 规则 |
|----------|----------|------|
| 页面 | `src/app/` | 只做展示和交互，不写核心业务公式 |
| 页面级组件 | `src/app/**/_components/` 或 `src/shared/components/` | 只被单页面使用的放页面内，多处复用的放 shared |
| 通用 UI 组件 | `src/shared/components/` | 不包含具体业务规则 |
| 业务逻辑 | `src/modules/[模块名]/` | 按业务能力归属，不放进 utils |
| 数据库 schema | `src/db/schema/` | 按业务模块拆分 |
| 服务端动作 | `src/server/actions/` | 负责页面到业务模块的调用编排 |
| 后台任务 | `src/server/jobs/` | 放导入、导出、统计、PDF 生成等耗时任务 |
| 对象存储 | `src/storage/` | 只封装文件保存、读取、权限和地址生成 |
| 单元测试 | `tests/unit/` | 覆盖公式、映射、推荐策略 |
| 集成测试 | `tests/integration/` | 覆盖数据库、导入导出、AI 降级 |
| 端到端测试 | `tests/e2e/` | 覆盖输入、生成、调整、导出主流程 |
| 样例数据 | `data-samples/` | 只能放脱敏样例，真实业务数据不放入源码 |
| 规格文档 | `specs/` | 产品、技术、结构、任务规划等项目定义 |
| 使用文档 | `docs/` | 面向用户、部署、运维 |

## 8. 首版不创建的目录

以下目录暂不建议在 V1.0 一开始创建：

| 目录 | 暂缓原因 |
|------|----------|
| `services/` | 首版不是微服务，不拆多个服务 |
| `packages/` | 首版不是 monorepo，避免结构过重 |
| `mobile/` | 首版使用 Web/PWA，不单独做移动端 App |
| `desktop/` | 首版不做 Windows 桌面软件 |
| `plugins/` | 当前没有插件化需求 |
| `tenants/` | 首版不做多租户 SaaS |

## 9. 后续演进

当业务规模上来后，可按以下方向演进：

- 多人协作增强：在 `auth` 和 `audit-log` 上扩展角色权限。
- 多公司使用：再考虑租户隔离，不提前创建多租户目录。
- 批量配纸：可在 `recommendation` 和 `server/jobs` 下增加批量任务。
- 供应商价格同步：可在 `master-data` 或新增 `supplier-sync` 模块承载。
- 离线能力：优先增强 PWA 离线草稿，再评估是否需要桌面版。
