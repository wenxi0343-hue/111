# 推荐不随纸箱数据变化

## 问题现象

用户在单次配纸页面修改纸箱数据后，生成结果仍容易保持同一套推荐方案，历史订单分析没有明显参与推荐。

## 复现方式

新增集成测试覆盖默认生成路径：只配置历史习惯仓储，不传测试专用 `getHistoricalHabitContextFn`，调用 `generateMatchingScheme` 生成方案。

修复前，历史习惯仓储没有被读取，`findLatestConfirmedHabitBatch` 调用次数为 0。

## 根因

`generateMatchingScheme` 只有在传入 `getHistoricalHabitContextFn` 时才读取历史习惯；真实页面路径不会传这个测试钩子，因此默认返回“无历史参考”。

同时，数据源创建逻辑在未显式配置数据源时会优先使用本地 `tmp_analysis/raw_papers.json`，导致已配置数据库时也可能绕开数据库历史习惯仓储。

## 修复

1. 生成方案主流程默认调用历史习惯读取逻辑。
2. 数据库路径默认使用 `createDrizzleHistoricalHabitRecommendationRepository`。
3. 本地原纸 JSON 只在未配置 `DATABASE_URL` 时作为兜底数据源。
4. 新增集成测试确保默认生成路径会读取历史习惯仓储并优先历史候选。

## 验证

- `vitest run tests/integration/matching/matching-actions.test.ts -t "historical habits"` 通过。
- `tsc --noEmit` 通过。
