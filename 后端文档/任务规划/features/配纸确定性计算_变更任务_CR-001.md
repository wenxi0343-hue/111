## 3. 变更详情

### 修改的验收标准

- **AC-005**: 生成结果页不展示候选明细
  - **Given** 存在不进入推荐的候选
  - **When** 用户点击生成方案并查看结果页
  - **Then** 系统不展示“不可推荐候选明细”区域，只展示不推荐原因汇总和推荐槽位内必要原因

- **AC-009**: 多个不推荐原因全部计入汇总
  - **Given** 某候选存在多个已识别问题
  - **When** 系统生成不推荐原因汇总
  - **Then** 系统按原因类型统计该候选的全部原因，而不是只统计第一条原因

### 技术变更

页面继续接收 `rejectedSummary` 和 `rejectedCandidates`。其中 `rejectedSummary` 保持用户可见，用于说明推荐不足原因；`rejectedCandidates` 保留在服务端结果结构中，供推荐槽位、测试和后续诊断使用，但 `box-spec-form.tsx` 不再渲染候选明细列表。

## 4. 增量任务

### 阶段一：收紧生成结果页展示

#### Task-07: 隐藏不可推荐候选明细

**通俗解释**：用户点生成后，只看到推荐方案和不推荐原因汇总，不再看到一长串不可推荐候选明细。

**做什么**：移除 matching 页面中 `rejectedCandidates` 明细区渲染，清理只服务于明细区的格式化函数和样式；保留不推荐原因汇总。

**涉及文件**：`src/app/(main)/matching/_components/box-spec-form.tsx`、`src/app/(main)/matching/matching.module.css`

**参考**：本文档 3 → AC-005, AC-009, AC-010

**依赖**：原 Task-06

**预估工时**：30 分钟

**验证标准**（TDD RED 阶段依据）：
- [ ] 服务端返回 `rejectedSummary` 和 `rejectedCandidates` → 页面展示“不推荐原因汇总”
- [ ] 服务端返回 `rejectedCandidates` → 页面不展示“不可推荐候选明细”
- [ ] 页面不出现 `rejected-candidate-*` 明细测试节点

---

#### Task-08: 回归验证

**做什么**：运行 matching 页面集成测试，确认推荐区、汇总区和主流程仍可用。

**依赖**：Task-07

**验证标准**：
- [ ] `tests/integration/matching/matching-page.test.tsx` 通过
- [ ] 推荐区仍展示经济型、安全型、均衡型
- [ ] 不推荐原因汇总仍显示各原因数量
