- [ ] 页面展示失败行 → 展示业务错误原因，不展示 SQL、堆栈或文件绝对路径。

### 阶段三：用户可以确认导入或取消导入

**阶段完成标准**：用户确认导入后，系统保存可入库订单，失败行不入库；异常和待确认订单可留痕但不参与统计；用户取消后，本次预览不会进入历史订单库。

#### [x] Task-03: 确认入库与取消导入闭环 🔒⚠️

**通俗解释**：用户看完预览后，可以决定正式保存这批订单，也可以取消；系统会保护好批次状态，避免误入库。

**做什么**：实现 `confirmHistoricalOrderImport` 和 `cancelHistoricalOrderImport`；确认时校验批次状态和尺寸区间确认状态；事务写入 `historical_orders`，跳过 `failed` 行；`statistical` 行写入 `isStatistical = true`，`pending` / `exception` 行写入 `isStatistical = false`；批次确认后不可重复确认；取消批次不写入历史订单。

**涉及文件**：`src/modules/historical-orders/import-commit.ts`、`src/modules/historical-orders/types.ts`、`src/server/actions/historical-order-actions.ts`、`tests/unit/historical-orders/import-commit.test.ts`、`tests/integration/historical-orders/historical-order-confirm.test.ts`

**参考**：技术方案 4 / `confirmHistoricalOrderImport`、`cancelHistoricalOrderImport`，技术方案 5 / 取消导入、纸质代码清洗、尺寸区间确认 → AC-002, AC-006, AC-009, AC-011, AC-017

**依赖**：Task-02

**预估工时**：140 分钟

**验证标准**（TDD RED 阶段直接转化为测试用例）：
- [ ] 批次不存在时调用 `confirmHistoricalOrderImport` → 返回 `DATA_NOT_FOUND`。

- [ ] 未登录调用确认或取消 → 返回 `AUTH_REQUIRED`，不修改批次状态。

#### [x] Task-04: 习惯摘要生成 ⚠️

**通俗解释**：系统会从干净可统计的历史订单里总结公司常用的层数、瓦型、纸厂和克重组合。

**做什么**：实现 `habit-summary.ts`；根据 `isStatistical = true` 订单生成产品名称/类别、尺寸区间、重量区间三类摘要；尺寸区间按用户确认的小箱/中箱/大箱口径归类；重量区间固定为 `≤20kg`、`20-30kg`、`≥30kg`；缺少重量的订单跳过重量维度但保留产品和尺寸维度；统计不读取、不计算历史价格或历史成本。

**涉及文件**：`src/modules/historical-orders/habit-summary.ts`、`src/modules/historical-orders/types.ts`、`tests/unit/historical-orders/habit-summary.test.ts`、`tests/integration/historical-orders/historical-order-summary.test.ts`
